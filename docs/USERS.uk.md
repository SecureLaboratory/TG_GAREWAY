# Користувачі: додавання, керування, звільнення

*[English](USERS.md) · Українська*

Є два типи облікових записів:

| Роль | Може | Не може |
|---|---|---|
| **Користувач** | Під'єднати *власний* обліковий запис Telegram, читати й надсилати повідомлення, відкривати перевірені файли й посилання | Користуватися адмін-панеллю |
| **Адміністратор** | Створювати користувачів, скидати паролі та 2FA, розблоковувати, вимикати/вмикати, переглядати статистику та стан фідів | Під'єднувати Telegram чи користуватися ним, читати чати, відкривати файли чи посилання, бачити будь-які секрети (сеанси, ключі автентифікатора, паролі) |

Людина, якій потрібні обидві ролі, отримує **два облікові записи**: адміністратора й користувача.

Кожен обліковий запис входить із **паролем і застосунком-автентифікатором** (TOTP: Microsoft
Authenticator, Google Authenticator, 1Password тощо). Єдиний вхід (SSO) заплановано.

**Мова:** вебзастосунок працює англійською та українською. Мова береться з налаштувань браузера;
змінити її можна кнопкою **English / Українська** у верхній панелі або на сторінці входу. Вибір
запам'ятовується в браузері.

## Де входять

| Хто | Адреса | Як |
|---|---|---|
| Користувачі | `https://<ваш домен>` (через ваш TLS-проксі) | з корпоративної мережі |
| Адміністратори | `http://localhost:8081/admin` | **лише через тунель до сервера.** Через публічну адресу адмін-панель недоступна: там `/admin` відповідає 404, а облікові записи адміністраторів не можуть увійти. За бажання оператор також відкриває `https://<ваш домен>/admin` для фіксованих IP-адрес (`ADMIN_ALLOWED_IPS`, [PRODUCTION.uk.md §4a](PRODUCTION.uk.md#4a-доступ-адміністраторів)) |
| Локально (Docker Desktop) | `http://localhost:8080` (користувачі) і `http://localhost:8080/admin` | лише локальний вхід |

Використовуйте в адресі `localhost`. Старіші розгортання приймають лише цю назву, тож там
`http://127.0.0.1:8081` відповідає *400 Bad Request*.

**Відкрийте тунель до адмін-панелі** зі свого ПК і тримайте вікно відкритим, поки працюєте:

```bash
ssh -L 8081:localhost:8081 <user>@<server>
```

Ваша хмара може пропонувати спосіб без відкритого порту SSH: сеанс переадресації портів, запущений
з її CLI. Підійде будь-який тунель до `localhost:8081` сервера.

Потім відкрийте в браузері **http://localhost:8081/admin**.

## 1. Створіть першого адміністратора (один раз, на сервері)

Щоб увійти у вебінтерфейс, потрібен адміністратор, тому першого створюють у командному рядку.
`-t` дає термінал для введення пароля (запитується двічі, щонайменше 12 символів):

```bash
ssh -t <user>@<server> \
  "cd /opt/tgviewer && sudo docker compose exec api python -m tgviewer.cli create-user admin --admin"
```

Або виконайте частину в лапках у будь-якій оболонці на сервері.

Локально: `docker compose exec api python -m tgviewer.cli create-user admin --admin`.

**Перший вхід:**
1. Відкрийте тунель і перейдіть на http://localhost:8081/admin.
2. Увійдіть з ім'ям користувача й паролем.
3. Відскануйте QR-код застосунком-автентифікатором і введіть 6-значний код.

## 2. Додайте користувача (вебінтерфейс)

1. Увійдіть в адмін-панель.
2. У розділі **Користувачі** введіть ім'я користувача. Воно може мати 3–64 символи: латинські
   літери, цифри, `.`, `-`, `_`. Добрий вибір — корпоративний логін, наприклад `j.smith`.
3. Оберіть роль:
   - **Користувач (працює з Telegram)** — для працівників;
   - **Адміністратор (без Telegram)** — для ще одного адміністратора.
4. Натисніть **Створити користувача**. **Тимчасовий пароль** показується **один раз**.
   Скопіюйте його.
5. Передайте користувачеві дві речі **різними каналами** (наприклад, адресу поштою, а пароль
   особисто чи телефоном):
   - адресу `https://<ваш домен>`;
   - тимчасовий пароль.

   Той, хто першим увійде з ним, налаштує автентифікатор, тож тримайте пароль у таємниці.

Список користувачів показує стан кожного облікового запису:

| Стан | Значення |
|---|---|
| активний / вимкнено | чи може обліковий запис входити |
| заблоковано | 5 невдалих спроб: блокування на 15 хвилин (або доки адміністратор не натисне *Розблокувати*) |
| тимчасовий пароль | користувач ще не входив або пароль скинуто |
| 2FA увімкнено / 2FA не налаштовано | чи налаштовано автентифікатор |
| Telegram: під'єднано | користувач під'єднав Telegram (лише стан; адміністратори ніколи не бачать сеансу) |

### Що робить новий користувач

Надішліть ці кроки разом з адресою:

1. Відкрийте `https://<ваш домен>` і ввійдіть зі своїм ім'ям користувача та тимчасовим паролем.
2. **Налаштуйте автентифікатор.** Відскануйте QR-код застосунком-автентифікатором на телефоні й
   введіть 6-значний код, який він покаже.
3. **Оберіть власний пароль** (щонайменше 12 символів).
4. **Прочитайте й прийміть умови користування та повідомлення про конфіденційність** (обраною
   мовою). Там перелічено, що зберігається (обліковий запис, зашифрований сеанс Telegram, файли на
   обмежений час, результати перевірок, події входу) і що ніколи не зберігається (текст
   повідомлень, паролі, контакти). Їх показують знову щоразу, коли текст змінюється, а переглянути
   їх можна будь-коли кнопкою **Конфіденційність** у верхній панелі.
5. **Під'єднайте Telegram.**
   - Введіть номер телефону в міжнародному форматі (`+380…`).
   - Введіть код входу. Сторінка показує, куди Telegram його надіслав. Зазвичай це **не SMS**:
     якщо ви ввійшли в Telegram на телефоні чи комп'ютері, код приходить **у застосунок
     Telegram** — повідомленням у чаті **«Telegram»** (із синьою позначкою). Якщо Telegram це
     дозволяє, з'являється кнопка на кшталт **Надіслати код в SMS**; вона стає активною після
     часу очікування, який задає Telegram.
   - Якщо у вашому обліковому записі ввімкнено двоетапну перевірку, введіть і цей пароль. Він
     передається лише в Telegram і не зберігається.
6. З'являться ваші чати. Надалі входьте з паролем і кодом із застосунку-автентифікатора.
   У каналах, де ви не адміністратор, і в групах, де писати заборонено, поля для повідомлення
   немає: замість нього підказка, що там можна лише читати.

Від'єднати Telegram можна будь-коли (кнопка **Від'єднати Telegram**). Шлюз також видно в
Telegram → Налаштування → Пристрої, де цей сеанс можна завершити з телефона.

## 3. Щоденні завдання (вебінтерфейс)

Кнопки розташовані поруч із кожним користувачем в адмін-панелі. Усі дії записуються в журнал
аудиту разом з адміністратором, який їх виконав.

| Ситуація | Кнопка | Результат |
|---|---|---|
| Забув пароль | **Скинути пароль** | Новий тимчасовий пароль показується один раз; усі сеанси користувача завершуються |
| Новий телефон / втрачено автентифікатор | **Скинути 2FA** | Під час наступного входу користувач налаштує новий автентифікатор; сеанси завершуються |
| Заблоковано після невдалих спроб | **Розблокувати** | Можна спробувати знову одразу |
| Звільняється або доступ треба припинити | **Вимкнути** | Не може входити, сеанси завершуються, **його сеанс Telegram на сервері відкликається** |
| Повертається | **Увімкнути** | Може входити знову; Telegram треба під'єднати знову |

**Власний** обліковий запис у вебінтерфейсі змінити не можна. Це може зробити інший адміністратор
або ви — через командний рядок нижче.

## 4. Командний рядок (на сервері)

Виконуйте в `/opt/tgviewer` від імені root на сервері (перед кожною командою —
`docker compose exec api python -m tgviewer.cli`):

| Команда | Що робить |
|---|---|
| `create-user <ім'я>` | Новий користувач. Запитує пароль (не тимчасовий, ≥ 12 символів) |
| `create-user <ім'я> --admin` | Новий адміністратор |
| `set-password <ім'я>` | Встановлює новий пароль і завершує сеанси (для власного облікового запису адміністратора) |
| `reset-totp <ім'я>` | Видаляє автентифікатор; його налаштовують знову під час наступного входу |
| `disable-user <ім'я>` | Вимикає обліковий запис і відкликає сеанс Telegram |
| `list-users` | Усі облікові записи та їхні позначки |

Приклад:

```bash
ssh -t <user>@<server> \
  "cd /opt/tgviewer && sudo docker compose exec api python -m tgviewer.cli set-password admin"
```

Для скриптів `--password-stdin` читає пароль зі стандартного вводу замість запиту.

## 5. Контрольний список під час звільнення

1. Адмін-панель → **Вимкнути** користувача. Це завершує його сеанси й відкликає сеанс Telegram на
   сервері.
2. Попросіть людину перевірити **Telegram → Налаштування → Пристрої** на телефоні. Сеансу шлюзу
   там уже не має бути; за потреби його можна завершити самостійно.
3. Перевірені файли користувача видаляються автоматично після строку зберігання
   (`CLEAN_RETENTION_DAYS`, типово 7 днів).

## 6. Аудит

**В адмін-панелі** картка **Події: входи та дії адміністраторів** показує останні події, нові
вгорі: хто й коли ввійшов, невдалі входи з причиною (невідоме ім'я користувача або вимкнений
обліковий запис, невірний пароль, невірний код автентифікатора, обліковий запис заблоковано,
адміністратор пробував публічну адресу), блокування та дії адміністраторів із зазначенням того, хто
їх виконав. Фільтри: *Лише невдалі*, *Лише входи*, *Лише дії адміністраторів*. Дані Telegram і
перевірки файлів там ніколи не показуються.

Події керування користувачами потрапляють у журнал аудиту JSON (`/data/audit/audit.jsonl` у
контейнері `api`, готовий для будь-якого збирача логів):

| Подія | Коли |
|---|---|
| `admin.user_created` | створено користувача (з роллю) |
| `admin.password_reset` / `admin.2fa_reset` | скидання адміністратором |
| `admin.user_unlocked` / `admin.user_disabled` / `admin.user_enabled` | змінено стан |

Кожна подія містить `actor_id` — адміністратора, який діяв. Успішні та невдалі входи й блокування
теж записуються. Паролі, коди й текст повідомлень — ніколи.

## Усунення проблем

| Проблема | Причина / рішення |
|---|---|
| `http://localhost:8081` не відкривається | Тунель не запущено (тримайте вікно `ssh -L …` відкритим) або локальний порт 8081 зайнятий (використайте `-L 18081:localhost:8081` і відкрийте `http://localhost:18081/admin`) |
| *400 Bad Request* | Ви використали `127.0.0.1` на сервері, що приймає лише `localhost`. Відкрийте `http://localhost:8081` |
| *404* на `https://<домен>/admin` | Так і має бути: адмін-панель доступна лише через тунель або з адрес у `ADMIN_ALLOWED_IPS`, якщо оператор його задав |
| Вхід адміністратора через публічну адресу пише «невірний пароль» | Так і має бути: адміністратори входять лише через адмінський вхід (або з адреси в `ADMIN_ALLOWED_IPS`) |
| Автентифікатор: «Невірний код» | Годинник телефона неточний. Увімкніть автоматичний час. Кожен код діє один раз |
| Обліковий запис заблоковано | Зачекайте 15 хвилин або попросіть адміністратора натиснути **Розблокувати** |
| Жоден адміністратор не може увійти | На сервері: `create-user <новий-адмін> --admin` або `set-password` / `reset-totp` для наявного адміністратора |
| «Адміністратор ще не налаштував облікові дані Telegram API» | Бракує `TG_API_ID` / `TG_API_HASH` (див. [PRODUCTION.uk.md](PRODUCTION.uk.md#3-налаштування-та-секрети)) |
| Немає SMS з кодом Telegram | Telegram спершу надсилає код у застосунок Telegram (чат «Telegram» на телефоні чи комп'ютері). Натисніть **Надіслати код в SMS**, якщо сторінка це пропонує. Якщо інших пристроїв із входом немає, Telegram сам вирішує, чи можливе SMS |
| «Telegram просить зачекати … с» | Забагато запитів коду: зачекайте вказаний час і спробуйте знову |
