# TG Viewer у робочому середовищі

*[English](PRODUCTION.md) · Українська*

Цей посібник підходить для будь-якого Linux-сервера з Docker — у вашому дата-центрі чи в будь-якій
хмарі. Він описує, **що** потрібно для робочого розгортання, а не консоль конкретного провайдера.
Кроки, специфічні для вашого провайдера (облікові записи, ідентифікатори мереж, скрипти),
тримайте у власному приватному репозиторії.

```
працівники ──HTTPS──▶ ваш TLS-проксі / балансувальник ──HTTP──▶ сервер :8080  edge (лише користувачі)
                      (сертифікат, лише корпоративні IP)              │
адміністратори ──SSH-тунель──────────────────────────────▶ сервер 127.0.0.1:8081  edge (адмінський вхід)
                                                                      ▼
                                      api (шлюз) ── egress (дозволений список) ──▶ Telegram, фіди
                                         │  clamav · postgres
```

## 1. Сервер

| Пункт | Рекомендація |
|---|---|
| ОС | Будь-який сучасний Linux з Docker Engine і **Docker Compose v2.24 або новішим** (теги `!reset`/`!override`) |
| Розмір | 2 vCPU, **4 ГБ RAM** (ClamAV потребує ~1,5 ГБ), **30 ГБ** диска |
| Диск | Зашифрований (LUKS або шифрування томів провайдера); щоденні знімки чи резервні копії |
| Swap | Вимкнений або зашифрований. Секрети в RAM не мають потрапляти на диск |
| Демон Docker | Ротація журналів (`max-size`), `"no-new-privileges": true`, `"live-restore": true` у `/etc/docker/daemon.json` |
| Вхідний брандмауер | Порт **8080 лише з вашого TLS-проксі**. SSH лише з адрес адміністраторів (або через bastion/VPN). Більше нічого |
| Вихідний брандмауер | TCP 443/80 (і діапазони IP Telegram на 443/80/5222). Контейнер `egress` звужує це ще більше |
| Сервіс метаданих хмари | Якщо він є (`169.254.169.254`), заблокуйте його для контейнерів, наприклад `iptables -I DOCKER-USER -d 169.254.169.254/32 -j REJECT` під час кожного запуску |

## 2. Образи

Можна збирати на сервері (`docker compose build`). Інший варіант: збирати в CI, надсилати до
вашого приватного реєстру й додати власний невеликий override, що задає `image:` для `api` та
`egress` і `build: !reset null`. Використовуйте фіксований тег версії для кожного випуску й
зберігайте попередній для відкату.

## 3. Налаштування та секрети

Запускайте стек із робочим override. Він вмикає захищені cookie та HSTS, задає дозволену назву
хоста, додає адмінський вхід на localhost і ставить вхідний проксі за TLS-проксі.

```
# /opt/tgviewer/.env  (налаштування)
COMPOSE_FILE=docker-compose.yml:docker-compose.prod.yml:docker-compose.secrets.yml
TGV_DOMAIN=tg.example.com            # назва хоста для користувачів (приймається лише вона)
TRUSTED_PROXY_CIDR=10.0.0.0/16       # адреси вашого TLS-проксі (для справжньої IP-адреси клієнта)
SECURITY_CONTACT=mailto:security@example.com
# за потреби: PUBLIC_BIND=10.0.0.5:8080 (слухати лише одну адресу), AUTO_SCAN_MAX_MB, … (.env.example)
# за потреби: ADMIN_ALLOWED_IPS=203.0.113.7  адмін-панель також через публічну адресу, з цих IP (4a)
```

**Секрети** можна передати двома способами.

| Спосіб | Як | Коли |
|---|---|---|
| **Файли (рекомендовано)** | Додайте `docker-compose.secrets.yml`. Перед кожним запуском записуйте по одному файлу на секрет у `SECRETS_DIR` (типово `/run/tgviewer-secrets`, **tmpfs** у RAM) з вашого сховища секретів: OpenBao agent, менеджер секретів хмари, sops тощо | робоче середовище |
| `.env` | Без `docker-compose.secrets.yml`. Покладіть `TG_API_ID`, `TG_API_HASH`, `POSTGRES_PASSWORD`, `ABUSECH_AUTH_KEY` у `.env`, доступний лише root | лише перші тести |

| Файл секрету | Вміст |
|---|---|
| `master_key` | 32 випадкові байти в base64 (`head -c 32 /dev/urandom \| base64`). Шифрує сеанс Telegram і секрет автентифікатора (TOTP) кожного користувача, тож сама лише копія бази даних не дає захопити облікові записи. **Створіть один раз, збережіть копію у сховищі секретів, ніколи не змінюйте.** Якщо ключ втрачено, усім користувачам доведеться знову під'єднати Telegram і налаштувати автентифікатор |
| `tg_api_id`, `tg_api_hash` | з https://my.telegram.org (на корпоративний номер) |
| `database_password` | довгий випадковий; задається один раз (Postgres його запам'ятовує) |
| `abusech_auth_key`, `vt_api_key` | необов'язкові; порожній файл, якщо не використовуються |

Із файлами секретів застосунок відмовляється запускатися без `master_key` (`REQUIRE_MASTER_KEY`),
тож він ніколи непомітно не створить новий ключ.

## 4. TLS-проксі / балансувальник

Підійде будь-що, що завершує TLS: nginx, HAProxy, Traefik або хмарний балансувальник.

- **Сертифікат** для `TGV_DOMAIN`, TLS 1.2+ (бажано 1.3). Переспрямування HTTP на HTTPS.
- **Пересилайте лише `TGV_DOMAIN`** на `http://<сервер>:8080`. Невідомим назвам хостів
  відповідайте 404.
- Зберігайте `X-Forwarded-For` (справжня IP-адреса клієнта потрібна для обмеження частоти запитів
  і аудиту) і задайте `TRUSTED_PROXY_CIDR` — адреси проксі.
- **Перевірка стану:** `GET /healthz` повертає 200 `{"ok":true}`, також коли звертаються за IP.
- Дозвольте довгі з'єднання (тайм-аут простою ≥ 120 с) для оновлень у реальному часі.
- Якщо можете, обмежте адреси клієнтів корпоративними діапазонами. За бажання поставте попереду WAF.
- **Ніколи не пересилайте порт 8081.** Адмінський вхід має лишатися локальним. Щоб відкривати
  адмін-панель через публічну адресу, використайте `ADMIN_ALLOWED_IPS` (розділ 4a).

## 4a. Доступ адміністраторів

Два способи, на ваш вибір:

| Спосіб | Налаштування | Примітки |
|---|---|---|
| **Адмінський вхід на localhost** (типово) | нічого не треба | `http://localhost:8081/admin` через SSH-тунель. Ззовні адмін-панель недоступна взагалі |
| **Публічна адреса з дозволених IP** | `ADMIN_ALLOWED_IPS=203.0.113.7,198.51.100.0/28` у `.env` | `https://<домен>/admin` працює з цих адрес клієнтів. З будь-якої іншої адреси — 404, і облікові записи адміністраторів звідти не можуть увійти. Вхід через localhost теж працює |

Якщо використовуєте список адрес:
- Додавайте лише адреси, які ви контролюєте, наприклад фіксовану IP-адресу офісу або вихідну адресу
  вашого VPN, і ніколи не домашні чи мобільні діапазони, якими користуються інші люди.
- Перевіряється справжня IP-адреса клієнта з `X-Forwarded-For`, якій довіряють лише від
  `TRUSTED_PROXY_CIDR`. Вказуйте там лише адреси самого проксі: якщо в цей діапазон потрапляють
  мережі клієнтів, клієнт звідти зможе видати себе за будь-яку адресу.
- Якщо ви також обмежуєте адреси клієнтів на TLS-проксі, дозвольте ці адреси й там.
- Адміністратори все одно входять із паролем і автентифікатором. Помилковий запис зупиняє запуск
  (`ADMIN_ALLOWED_IPS: …` у `docker compose logs api`).

## 5. Запуск як служби

Використовуйте модуль systemd, щоб секрети записувалися перед запуском Compose і видалялися після
зупинки:

```ini
[Unit]
Description=TG Viewer
After=docker.service network-online.target
Requires=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
TimeoutStartSec=1800
WorkingDirectory=/opt/tgviewer
EnvironmentFile=/opt/tgviewer/.env
# ExecStartPre=/usr/local/bin/tgviewer-fetch-secrets   # ваш скрипт: сховище секретів -> /run/tgviewer-secrets
ExecStart=/usr/bin/docker compose up -d --remove-orphans
ExecStop=/usr/bin/docker compose down
ExecStopPost=/bin/rm -rf /run/tgviewer-secrets

[Install]
WantedBy=multi-user.target
```

`systemctl enable --now tgviewer`. Перший запуск триває кілька хвилин, поки ClamAV завантажує
сигнатури.

## 6. Перевірка

```bash
cd /opt/tgviewer
docker compose ps                                            # postgres, clamav healthy; решта Up
curl -s -H "Host: tg.example.com" http://127.0.0.1:8080/healthz                       # {"ok":true}
curl -s -o /dev/null -w '%{http_code}\n' -H "Host: tg.example.com" http://127.0.0.1:8080/admin   # 404
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8081/admin                  # 200
curl -sI https://tg.example.com/ | grep -i strict-transport                           # HSTS є
```

Також переконайтеся, що:
- контейнер `api` не може напряму вийти в інтернет;
- у `docker compose logs egress` вихідні запити йдуть лише до Telegram і сайтів фідів;
- у `docker compose exec api env` немає значень секретів.

## 7. Перший адміністратор і користувачі

Див. [USERS.uk.md](USERS.uk.md). Коротко: створіть першого адміністратора на сервері
(`docker compose exec api python -m tgviewer.cli create-user admin --admin`), відкрийте тунель
(`ssh -L 8081:localhost:8081 <сервер>`) і перейдіть на http://localhost:8081/admin.

## 8. Експлуатація

| Завдання | Як |
|---|---|
| Оновлення | Нові образи або `git pull` + `docker compose build`, потім `systemctl restart tgviewer`. Спершу зробіть резервну копію |
| Відкат | Попередній тег образу чи коміт, потім перезапуск |
| Резервні копії | Томи `appdata` і `pgdata` (або весь диск) та **головний ключ** у сховищі секретів. Без ключа резервна копія не зможе розшифрувати під'єднані сеанси |
| Журнали | `docker compose logs -f api` · `docker compose logs egress` · ClamAV: `docker compose exec clamav tail -f /var/log/clamav/clamd.log` |
| Журнал аудиту | `/data/audit/audit.jsonl` у контейнері `api` (рядки JSON) |
| Оновлення ОС | Щомісяця, потім перезавантаження. Служба запускається сама |

## Контрольний список

- [ ] HTTPS працює з дійсним сертифікатом; HTTP переспрямовується; невідомі назви хостів отримують 404
- [ ] `https://<домен>/admin` дає 404 (з `ADMIN_ALLOWED_IPS`: з кожної адреси поза списком); адмін-панель працює через тунель
- [ ] Порт 8080 доступний лише з TLS-проксі; 8081 прив'язаний до `127.0.0.1`
- [ ] Секрети лише у сховищі секретів і в `/run/tgviewer-secrets` (tmpfs); не в `.env`, не в образах, не в git
- [ ] Копію головного ключа збережено у сховищі секретів
- [ ] Контейнери не мають доступу до сервісу метаданих хмари
- [ ] Диск зашифровано; резервні копії чи знімки заплановано
- [ ] Адмін-панель → *Рушії та фіди*: видно версію ClamAV, фіди оновлено
