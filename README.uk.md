# TG Viewer

*[English](README.md) · Українська*

Вебшлюз для власного розгортання, через який працівники користуються **власним обліковим записом
Telegram** із корпоративної мережі. Кожне вкладення й кожне посилання перевіряються, перш ніж
потрапити на ПК.

- Працівники відкривають Telegram у браузері через шлюз. Клієнт Telegram працює на сервері, тож
  сам Telegram не мусить бути доступним з робочих станцій.
- **Кожне вхідне вкладення й посилання перевіряється автоматично щойно надходить**, ще до того, як
  його хтось відкриє: ClamAV, YARA, перевірка документів, правила для типів файлів, локальні фіди
  загроз.
- **Вихідні файли** проходять ту саму перевірку, а також правила DLP (ключі, токени, номери карток,
  мітки конфіденційності).
- **Адміністратори** керують користувачами й бачать статистику, але **не можуть користуватися
  Telegram, читати чати чи бачити будь-які секрети**. Адмін-панель доступна лише із самого сервера,
  через SSH-тунель.
- **Приватність:** текст повідомлень ніколи не зберігається й не записується в журнали. Жодні дані
  про файли чи посилання працівників не передаються третім сторонам (VirusTotal — необов'язково і
  лише за хешем, коду для вивантаження файлів немає).

> **Стан:** робочий MVP. Спершу спробуйте з тестовим обліковим записом Telegram, а не з обліковим
> записом справжнього працівника.

## Як це працює

```
браузер працівника ──HTTPS──▶ вхідний проксі (Caddy) ──▶ шлюз (FastAPI + Telethon) ──▶ egress-проксі ──▶ Telegram
                              :8080 користувачі               │  черга перевірок         (лише дозволений список)
                              127.0.0.1:8081 адміністратори   ├─▶ ClamAV, YARA, oletools, PDF, перекодування зображень
                                                              └─▶ Postgres (користувачі, вердикти, зашифровані сеанси)
```

| Контейнер | Роль | Інтернет |
|---|---|---|
| `edge` | Вхідний проксі. Публічний вхід для користувачів; адмінський вхід лише на localhost | ні |
| `api` | Шлюз: вебінтерфейс, клієнти Telegram, перевірка файлів, перевірка посилань, DLP | **прямого виходу немає**; лише через `egress` |
| `egress` | Дозволений список Squid: діапазони IP Telegram, сайти фідів і сигнатур | так (з фільтрацією) |
| `clamav` | Антивірус і оновлення сигнатур | через `egress` |
| `postgres` | База даних | ні |

## Що вміє

**Перевірка.** Автоматично щойно надходить:

| Що | Коли | Типово |
|---|---|---|
| Посилання (у тексті, приховані, кнопки ботів і каналів) | щойно надходять | завжди |
| Вкладення (документи, архіви, відео тощо) | щойно надходять: завантажуються в карантин і перевіряються | ≤ 50 МБ, особисті чати, групи, боти (`AUTO_SCAN_*`) |
| Фото | коли відкривається чат | `AUTO_SCAN_PHOTOS=false` |
| Перевірені вхідні зображення | легкий шлях: перевірка справжнього типу, пошук за хешем і **перекодування**; на ПК потрапляє лише перекодована копія | `IMAGE_FAST_PATH=true` |
| Більші файли, дописи каналів | коли користувач натискає *Перевірити* | |

- Рушії: політика типів файлів (справжній тип, а не назва), перевірка ZIP з обмеженнями проти
  zip-бомб, **ClamAV**, **YARA** (вбудовані правила + YARA Forge), oletools (макроси, віддалені
  шаблони), активний вміст PDF, локальні фіди хешів. Завантаження доступне лише після чистого
  вердикту.
- **Посилання** переписуються на `/go/<id>` і перевіряються під час отримання та ще раз під час
  переходу (локальні фіди, Tranco, евристики). Результат — попередження, блокування або перехід.
- **Вихідні файли** проходять ту саму перевірку плюс DLP; результат — надіслати, попередити
  (користувач підтверджує) або заблокувати.

**Облікові записи й доступ.**
- Вхід у два кроки: пароль, потім застосунок-автентифікатор (налаштовується в браузері під час
  першого входу). Паролі від адміністратора тимчасові, їх треба змінити.
- Ролі: користувачі під'єднують і використовують свій Telegram, адміністратори лише керують
  користувачами й переглядають статистику.
- Екран згоди перед під'єднанням. Користувачі можуть від'єднатися будь-коли, а вимкнення
  користувача також відкликає його сеанс Telegram.
- Під'єднані сеанси Telegram і секрети автентифікаторів зашифровані (AES-256-GCM) **головним
  ключем**, який ваше розгортання бере зі сховища секретів (`MASTER_KEY_FILE`), тож сама лише копія
  бази даних не дає захопити облікові записи. Див. [docs/PRODUCTION.uk.md](docs/PRODUCTION.uk.md).

**Експлуатація.**
- Вебзастосунок **англійською та українською**: мова береться з браузера, є перемикач у верхній
  панелі. Повідомлення сервера й попередження про посилання — тією самою мовою.
- Сторінка статистики для адміністратора та журнал аудиту JSON (рядки JSON, легко передати в будь-який збирач логів).
- Клієнти Telegram лишаються на зв'язку на сервері й надолужують повідомлення, пропущені під час
  простою.

**Фіди загроз** завантажуються й перевіряються локально:

| Фід | Потрібно |
|---|---|
| OpenPhish, список Tranco, правила YARA Forge | нічого |
| MalwareBazaar, URLhaus (abuse.ch) | безкоштовний `ABUSECH_AUTH_KEY` з https://auth.abuse.ch |
| VirusTotal (необов'язково, `REPUTATION_MODE=local+vt`) | `VT_API_KEY`. Лише GET-запити за хешем; файли ніколи не вивантажуються |

Стан кожного фіду видно в адмін-панелі.

## Вимоги

- **API ID і hash Telegram**: зареєструйте застосунок на https://my.telegram.org із
  **корпоративним** номером телефону. Один застосунок обслуговує всіх користувачів.
- Docker Desktop або Docker Engine з Compose v2.24 чи новішим.
- Для робочого середовища: Linux-сервер, TLS-проксі чи балансувальник і сховище секретів
  ([PRODUCTION.uk.md](docs/PRODUCTION.uk.md)).

## Локальний запуск

```bash
cp .env.example .env                  # заповніть TG_API_ID і TG_API_HASH; ABUSECH_AUTH_KEY — за бажанням
docker compose up -d --build          # перший запуск триває кілька хвилин (сигнатури ClamAV)
docker compose exec api python -m tgviewer.cli create-user admin --admin
```

1. Відкрийте http://localhost:8080/admin і ввійдіть як `admin`. Локально вхідний проксі слухає лише
   `127.0.0.1`, тож він і є адмінським входом. У робочому середовищі адмін-панель переходить на
   окремий порт, доступний лише з localhost; її також можна відкрити через публічну адресу для
   дозволених IP (`ADMIN_ALLOWED_IPS`, див. [docs/PRODUCTION.uk.md](docs/PRODUCTION.uk.md#4a-доступ-адміністраторів)).
2. Налаштуйте застосунок-автентифікатор (відскануйте QR-код).
3. У розділі **Користувачі** створіть звичайного користувача. Тимчасовий пароль показується один
   раз.
4. Вийдіть і ввійдіть як цей користувач на http://localhost:8080. Налаштуйте автентифікатор,
   змініть пароль, прийміть екран згоди й під'єднайте Telegram.

Повний посібник — у [docs/USERS.uk.md](docs/USERS.uk.md).

## Тести

```bash
docker compose run --rm --no-deps api python -m pytest -q
```

Вони охоплюють контроль доступу (перевірка всіх маршрутів для кожної ролі), вхід і блокування,
адмінський вхід, заголовки безпеки, рушії перевірки, обмеження VirusTotal лише на GET і наявність
кожного тексту обома мовами.

## Структура репозиторію

| Шлях | Вміст |
|---|---|
| `app/` | Шлюз (Python, FastAPI, Telethon), фронтенд у `app/tgviewer/static/`, тести в `app/tests/` |
| `edge/` | Вхідний проксі Caddy: `Caddyfile` (локально), `Caddyfile.proxy` (робоче середовище, за TLS-проксі) |
| `egress/` | Проксі Squid з дозволеним списком для вихідного трафіку |
| `clamav/` | Налаштування демона ClamAV і freshclam |
| `docker-compose.yml` | Стек (локально й основа для робочого середовища) |
| `docker-compose.prod.yml` | Override для робочого середовища: за TLS-проксі, захищені cookie, адмінський вхід на localhost |
| `docker-compose.secrets.yml` | Секрети як файли (зі сховища секретів, у RAM) замість `.env` |
| `docs/` | Посібники з розгортання та для користувачів |

**Тримайте своє розгортання окремо.** Цей репозиторій загальний: у ньому немає налаштувань
конкретного провайдера, ідентифікаторів облікових записів, доменів чи секретів. Тримайте їх в
окремому **приватному** репозиторії:
- `.env` вашого сервера;
- скрипти й політики вашої хмари чи провайдера;
- override для вашого реєстру образів;
- ідентифікатори ваших ресурсів.

Секрети зберігайте лише у сховищі секретів.

## Відомі обмеження

- Власний телефон працівника все одно може користуватися тим самим обліковим записом Telegram, і
  те, що відкривається там, не перевіряється. Шлюз захищає корпоративну мережу, а не телефон.
- Усі клієнти Telegram працюють в одному процесі, черга перевірок — усередині процесу (без
  Redis/SQS).
- Файли зберігаються на локальному томі, а не в S3.
- Локальні облікові записи з TOTP; SSO (OIDC) у планах.
- ClamAV — єдиний антивірусний рушій; другий рушій і пісочниця CAPE у планах.
